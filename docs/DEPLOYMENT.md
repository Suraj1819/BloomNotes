# BloomNotes — Deployment Guide

## Prerequisites

- A Supabase project: https://supabase.com
- Node.js 18+ for both client and server.
- A hosting provider:
  - Frontend: Vercel or Netlify (static hosting, SPA).
  - Backend: Render, Railway, Fly.io, or any Node host.
  - DB / Storage / Auth: Supabase (managed).

## 1. Database

1. Open the Supabase dashboard → SQL Editor.
2. Paste the contents of `supabase/migrations/0001_init.sql` and run it.
3. Verify the `vault` bucket appears under Storage (private).
4. Confirm tables exist with RLS enabled.

## 2. Backend (Render example)

1. Push the `server/` folder to a Git repo.
2. Create a new Web Service on Render pointing to that repo / subdirectory.
3. Build command: `npm install`
4. Start command: `npm start`
5. Environment variables:
   ```
   PORT=5000
   NODE_ENV=production
   CLIENT_URL=https://your-frontend.vercel.app
   SUPABASE_URL=https://your-project.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=<from Supabase — Project Settings → API>
   SUPABASE_ANON_KEY=<from Supabase — Project Settings → API>
   SESSION_TTL_MS=86400000
   RATE_LIMIT_MAX=300
   VAULT_MAX_FILE_SIZE=26214400
   ```
6. Deploy and confirm `/health` responds.

## 3. Frontend (Vercel example)

1. Push the `client/` folder to a Git repo (or the same repo, root-level).
2. Create a new Vercel project pointing to `client/`.
3. Build command: `npm run build`
4. Output directory: `dist`
5. Environment variables:
   ```
   VITE_API_URL=https://your-backend.onrender.com/api/v1
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_ANON_KEY=<anon key>
   ```
6. Add a SPA rewrite so all routes serve `index.html`:
   - Vercel: `vercel.json` with `{ "rewrites": [{ "source": "/(.*)", "destination": "/" }] }`
   - Netlify: `_redirects` file with `/*  /index.html  200`

## 4. Supabase Auth settings

- Authentication → URL Configuration:
  - Site URL: `https://your-frontend.vercel.app`
  - Redirect URLs: `https://your-frontend.vercel.app/**`, `http://localhost:5173/**`
- Email templates: customize as desired; default templates work.

## 5. Storage settings

The migration already creates the `vault` private bucket and policies. Confirm:
- Bucket `vault` exists and is **not public**.
- Storage policies include `vault_storage_*` rules that check `(storage.foldername(name))[1] = auth.uid()::text`.

## 6. Production checklist

- [ ] `0001_init.sql` ran without errors on Supabase.
- [ ] Backend deployed; `/health` returns `{"ok": true}`.
- [ ] Frontend deployed; landing page loads.
- [ ] Registration → email verification → first login flow works.
- [ ] Creating a note assigns a random theme; reopening the note applies the same theme.
- [ ] Closing the note restores the parent theme.
- [ ] Vault upload + download works in production.
- [ ] 24h inactivity logout works (lower `SESSION_TTL_MS` for testing).
- [ ] No `service_role` key visible in the deployed client bundle.
- [ ] CORS configured so only your frontend origin can call the API.

## 7. Local development

```bash
# 1) Run the migration on a Supabase project (SQL Editor).

# 2) Backend
cd server
cp .env.example .env  # fill in
npm install
npm run dev

# 3) Frontend (separate terminal)
cd client
cp .env.example .env  # fill in
npm install
npm run dev
```

Open http://localhost:5173.

## 8. Known limitations

- Reminder notifications are generated by a server-side polling job (every 60s). There is no realtime push; the client polls `/notifications` (which does not extend the session).
- Supabase access tokens (~10 min) cannot be revoked server-side. After the 24h inactivity policy revokes the application session, RLS still blocks data access, but a stolen token may briefly authenticate. Refresh-token revocation happens on the next session check.
- The provided multipart parser in `vaultController.js` is intentionally minimal (no streaming). For files approaching the 25 MB limit, consider adding `multer` + a streaming upload to Supabase in a follow-up.
- pg_trgm is loaded opportunistically. If your Supabase project disallows `create extension`, the trigram index is skipped silently; basic `ilike` search still works.
